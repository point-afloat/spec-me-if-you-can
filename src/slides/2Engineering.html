Code has to be read, changed, debugged and kept alive for years; that is where most of the cost is, not in typing it. - Bad code is expensive because every later change has to work around it, and the cost compounds. - AI makes bad code faster to produce too, so you can now create the expensive kind quicker than ever. That is why "the most expensive it's ever been": the supply of bad code has never been cheaper. - Context: Pocock says it against the idea that code is cheap, so you can regenerate it from a spec and never look. Do not claim he is against specs: he is against specs-to-code with nobody owning the design. - Bridge to the next slides: so how much does AI really speed up the whole job? That is Amdahl.
